# NET012 — SSH Lifeline NIC Protection

## Statement

Before reconfiguring any NIC (moving it into a namespace, assigning a static
test IP, forcing a link speed, or bouncing the adapter), the framework shall
identify the NIC that carries the operator's live management session and
exclude it from the test set.

The lifeline NIC shall be identified from the **local address of the active
inbound management connection** (an established TCP session on SSH port 22 or
RDP port 3389), which is the wire the operator is actually reaching the host
over — this is more reliable than the default-route NIC, because routing may
send the management session out a different interface than the one with the
lowest route metric.

This detection shall be **unconditional**: it runs and adds the session NIC to
the exclusion set *in addition to* any management MAC (`_net_exclude_macs`) or
name (`-Lifeline` / `-Skip`) the operator configured — it is never skipped just
because an exclusion was already specified. A configured MAC that happens to
name a different NIC must not disable the session-based safety net.

## Rationale

Safety net for NET011 — even if the operator forgets to exclude the lifeline,
or pins the wrong MAC, the framework must never reconfigure the NIC carrying
the session it is being driven over. Doing so drops the operator's SSH/RDP
connection mid-run, and because the NIC is left on a static test IP and forced
speed until the run completes, the session cannot be re-established to recover.
Making the session-NIC detection a fallback (only when nothing else is
excluded) is therefore unsafe: a mis-typed or wrong management MAC silently
disables the one check that would have protected the live connection.

## Scope

All scripts and shared libraries in the framework.

## Implications

1. The session-carrying NIC (SSH 22 / RDP 3389) is detected from the active
   connection's local address and always excluded, regardless of any
   configured MAC / name exclusions.
2. A local-console run has no inbound management session, so the detection
   correctly excludes nothing.
3. Operator-configured exclusions (`_net_exclude_macs`, `-Lifeline`, `-Skip`)
   are additive to, not a replacement for, the session-based detection.
- Non-compliance must be corrected before merge.
