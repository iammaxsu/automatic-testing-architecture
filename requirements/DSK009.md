# DSK009 — fio Engine and Write-Consistency Flags Aligned with KDiskMark v3.2.0

## Statement

The fio invocation in disk_test.sh shall use the following flags by default to align with KDiskMark v3.2.0 behaviour:

- `--ioengine=libaio` — asynchronous I/O engine (replaces `psync`); required for meaningful queue-depth scaling.
- `--randrepeat=0` — disable the deterministic random seed so each run uses a varied access pattern.
- `--end_fsync=1` — call `fsync()` after each write job completes to ensure data is committed.

Default values shall be defined in `config.sh` as `_fio_ioengine`, `_fio_randrepeat`, and `_fio_end_fsync` and propagated to every `fio` invocation via `run_fio()`.

## Rationale

`psync` performs synchronous I/O one request at a time, making `--iodepth` > 1 irrelevant and producing results that cannot be compared with KDiskMark or CrystalDiskMark. `libaio` allows the kernel to issue multiple outstanding requests and is the standard for storage benchmarking on Linux. `randrepeat=0` and `end_fsync=1` match the KDiskMark v3.2.0 profile defaults, enabling direct comparison.

## Scope

`src/bash-shell/disk_test.sh` and `src/bash-shell/config.sh`.

## Implications

- Changing the I/O engine may produce different absolute numbers on the same device compared to previous `psync` runs; historical baseline data collected with `psync` is not directly comparable.
- `end_fsync=1` combined with `--direct=1` is effectively a no-op for reads (no page-cache data to flush); the flag is safe to pass unconditionally.

## Verification

Code Review: confirm `config.sh` sets `_fio_ioengine=libaio`, `_fio_randrepeat=0`, `_fio_end_fsync=1`; confirm `run_fio()` in `disk_test.sh` passes all three to `fio`.
