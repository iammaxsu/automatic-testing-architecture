# LOG001 — Logs Directory Creation

## Statement

A folder named `logs/` shall exist (or be created) before any test output is
written.

By default it shall be located **in the directory containing the script
being run** — not in the process working directory. Running a script from
an unrelated directory shall not change where its output goes.

An explicit output path supplied by the operator (`--out`, `--report`, or
the equivalent shell variable) overrides this default and is used verbatim;
if relative, it resolves against the working directory as the operator
typed it.

## Rationale

The output location must be a property of the deployment, not of the shell
the operator happened to be sitting in. If it follows the working directory,
the same deployment scatters log trees across the filesystem: results land
where nobody looks, the Ansible fetch step (which collects
`{{ deploy_dir }}/logs`) silently misses them, and — because session state
lives only under the output root (LOG025) — deleting `logs/` to force a
clean run can clear a tree the next run will not even consult.

The original wording, "in the script working directory", could be read as
either the script's directory or the process's. Bash and PowerShell
implemented the first reading; Python implemented the second, and the two
halves of the framework disagreed for as long as that went unnoticed
(BUG0042). The statement above names the directory explicitly so the
ambiguity cannot recur.

Anchoring to the script also means a deployment may be copied anywhere and
carries its own logs with it — `/home/adlink/Downloads/` and
`/home/adlink/Desktop/` each keep their own `logs/`, which is the intended
behaviour, not a conflict.

## Scope

All scripts and shared libraries in the framework:

| Layer      | Anchor                                              |
|------------|-----------------------------------------------------|
| Bash       | `function.sh` `log_dir()` → `_tool_path`            |
| PowerShell | `$_script_root` (`Split-Path -Parent $MyInvocation`) |
| Python     | `config.LOG_DIR` / `REPORT_DIR` → `_TOOL_PATH`      |
| Composite  | `run_tests.sh` → `$SCRIPT_DIR/logs`                 |

## Implications

1. Language-level "current directory" defaults (`"./logs"`, `Path("logs")`,
   a bare filename) must not be used for output paths. Each layer resolves
   its own script location instead.
2. This applies to every default output artefact, not just the directory —
   counter files, session state, and reports included.
3. A relative path the operator passes explicitly is left alone. The rule
   governs defaults, not overrides.
4. Ansible orchestration is unaffected: the playbooks already `cd` into
   `deploy_dir` before invoking a test, so both readings coincided there.

## Verification

- `src/python/output_path_unittest.py` — asserts the Python defaults are
  absolute, sit beside the scripts, and do not change when the module is
  imported from an unrelated working directory.
- Code review for the bash and PowerShell layers, which resolve the script
  path directly (`readlink -f` / `$MyInvocation.MyCommand.Definition`).
