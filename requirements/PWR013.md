# PWR013 — Reboot Test Initial State Normalisation

## Statement

`reboot.py` shall normalise the DUT to a testable (alive) state before its first
reboot cycle by calling `function.init_dut()` (FWK031). It shall not assume the
DUT is already online — in particular it must recover from the DUT being powered
**off** (the state in which `power_cycle.py` always leaves it).

`reboot.py` shall:
1. Construct a `RelayController` on `--pin` (default `config.GPIO_PIN`) unless the
   pin is unset.
2. Call `init_dut()` with `--type`, `--boot-timeout`, `--off`, the ATX press
   durations, and `--init-wait`.
3. Abort with the returned `method` logged if `init_dut()` reports failure.
4. Skip init entirely when resuming an interrupted session (LOG023) or in
   `--dry-run`.

The escalation behaviour (already-up → power-on press → forced power cycle → give
up; or wait-only when no GPIO) is defined by FWK031 and is identical across tests.

## Rationale

`power_cycle.py` always ends with the DUT powered **off** — correct and intentional
(PWR009/PWR010). Without init, `reboot.py` would fail immediately whenever it runs
after `power_cycle.py`, because its first cycle issues an SSH reboot that requires
the DUT to be online.

Earlier designs solved this with a `--leave-on` flag on `power_cycle.py` (leave the
DUT powered after the last cycle) or by requiring the operator to pass init flags.
Both fail the moment the operator forgets, and both constrain composite test order.
Delegating to `init_dut()` removes the operator burden entirely and lets `reboot.py`
appear anywhere in a composite sequence. `--leave-on` is consequently removed from
`run_tests.sh`.

## Scope

`src/python/reboot.py`; depends on `function.init_dut()` (FWK031),
`LivenessChecker.is_up()`, and `RelayController`. Config: `GPIO_PIN`, `POWER_TYPE`,
`ATX_SHORT_PRESS_SEC`, `ATX_LONG_PRESS_SEC`, `OFF_TIME_SEC`, `BOOT_TIMEOUT_SEC`,
`INIT_WAIT_SEC`.

## Implications

1. `--pin` defaults to `config.GPIO_PIN` (not `None`): an operator who has set the
   relay pin once in `config.py` gets automatic recovery with no extra flags.
2. `--init-wait` is now a GPIO-unavailable fallback only (wait for a still-booting
   DUT); GPIO recovery supersedes it when a pin is available.
3. `reboot.py` imports `RelayController` solely for init; the reboot cycles
   themselves remain pure SSH and use no GPIO.
4. `run_tests.sh` forwards `--pin` and `--type` to both phases via `COMMON_ARGS`;
   the `--leave-on` flag and its auto-logic are removed.

## Verification

Code Review:
- Confirm `reboot.py` builds the relay from `--pin` and calls `init_dut()` before
  the first cycle, skipping it when resuming or in dry-run.
- Confirm `--pin` defaults to `config.GPIO_PIN`.
- Confirm `run_tests.sh` no longer references `--leave-on`.

Manual test (composite):
1. `power_cycle.py --cycles 3 ...` — DUT ends powered off.
2. `reboot.py --cycles 3 ...` (no extra flags) — init powers the DUT on, then 3
   reboot cycles complete.
