# FWK033 — Privilege Precondition Check

## Statement

Any test-framework script that requires elevated (administrator / root)
privileges to complete its work shall verify that it is running with those
privileges **as its first executable action**, before producing any other
output or making any change. If the privilege check fails, the script shall:

1. Print a single, clear error stating that elevation is required and that
   **nothing has been changed**.
2. Print how to re-run correctly (both local and remote/SSH paths where
   applicable).
3. Exit immediately with a non-zero status.

The check shall be a positive runtime test of the effective token, not only a
declarative directive (e.g. PowerShell `#Requires -RunAsAdministrator`), because
declarative directives are unreliable across execution contexts (notably
non-interactive SSH sessions and UAC-filtered administrator tokens). A
declarative directive may be retained as a secondary backstop.

## Rationale

`setup_dut.ps1` configures the entire test environment (SSH, firewall, power
scheme, Task Scheduler, security policy). Run without elevation it does not fail
cleanly: many steps use `try/catch` or `-ErrorAction SilentlyContinue`, so the
script appears to "complete" while silently skipping every privileged operation.
The operator sees a wall of step messages, the real problem scrolls off-screen,
and the misconfiguration only surfaces later as confusing test failures.

Checking privileges first — before any other output — turns a silent, late,
hard-to-diagnose failure into an immediate, obvious, safe one. Stating "nothing
has been changed" lets the operator re-run with confidence rather than wondering
whether a half-configured machine needs cleanup.

## Scope

`src/powershell/setup_dut.ps1` (administrator). Any future script with the same
precondition: other privileged Windows setup scripts, and root-requiring Linux
setup/test scripts (where the equivalent check is `id -u` / `EUID -eq 0`).

Scripts that do **not** require elevation (e.g. `reboot.ps1`, which is run
non-elevated over SSH or locally by design) shall **not** add such a check; they
must instead be written so their privileged side-effects are unnecessary at run
time (see PWR011 / BUG0026: the scheduled task is configured once by the elevated
`setup_dut.ps1`, so `reboot.ps1` never needs to modify it).

## Implications

1. The check is the first executable statement, ahead of the version banner and
   any step output.
2. On Windows the check is:
   `([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)`.
3. On Linux the check is `[ "$(id -u)" -eq 0 ]` (or `$EUID -eq 0`).
4. The failure message must explicitly say no changes were made.
5. Exit status is non-zero so callers (Ansible, wrapper scripts) can detect the
   precondition failure.
