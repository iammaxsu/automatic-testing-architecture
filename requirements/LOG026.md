# LOG026 — Bounded Auto-Resume and Explicit Session Announcement

## Statement

Auto-resume of an incomplete session (LOG023) shall be **bounded by age**.
A session whose `updated_at` is older than a configurable window
(`RESUME_MAX_AGE_HOURS`, default 24) shall be treated as **abandoned**: the
run shall start a new session instead, and shall report each skipped
session and the reason on the console.

Every run shall announce, **before the first iteration**, whether it is a
NEW session or is RESUMING an existing one. The announcement shall state
the `session_id`, the session directory, the iteration range this run will
execute, and — when resuming — how many iterations were already recorded
and that this run appends to the same `result.json`.

Resolution order shall be:

| Order | Input                     | Effect                                        |
|-------|---------------------------|-----------------------------------------------|
| 1     | `--new-session`           | always start a new session                    |
| 2     | `--resume`                | resume an incomplete session at any age       |
| 3     | `--resume-max-age HOURS`  | auto-resume only within HOURS                 |
| 4     | (default)                 | auto-resume only within 24 h                  |

`--new-session` and `--resume` together shall be rejected as a usage error.
`--resume-max-age 0` shall disable auto-resume entirely; a negative value
shall restore unbounded auto-resume.

## Rationale

LOG023 made an interrupted run resumable, which is correct for its intended
case: the operator aborts a 300-cycle run, fixes the bench, and continues
within the hour. But the implementation resumed *any* incomplete session
regardless of age, and reported the decision as a single parenthetical
`(RESUMING)` among twenty startup fields.

Both properties fail the operator in the same direction — silently running
something other than what was asked for:

1. **Unbounded age.** A session aborted days or weeks earlier stays
   `status: running` forever. The next unrelated run against the same DUT
   silently continues it, merging cycles recorded on a possibly different
   bench state into one `result.json`, and executing `m - n` cycles instead
   of the `m` the operator had in mind.
2. **Invisible decision.** Whether a run is new or resumed is the single
   most consequential fact about it — it decides how many cycles actually
   execute and which artefacts grow. Buried in a field list, it is missed.

The observed consequence is that operators learn to `rm -rf logs/` before
every run as a defensive ritual, purely to be certain of a clean start.
That works — session state lives only under `--out` (LOG025), so deleting
it does force a new session — but it destroys prior results to obtain a
guarantee the tool should have stated outright, and it silently does the
wrong thing when the deleted `logs/` is not the one the run resolves
(`LOG_DIR` is relative to the working directory).

BUG0041 fixed the adjacent case where an *explicit* `--cycles` disagreed
with the resumable session. This requirement covers the case where the
operator passes nothing at all and simply expects a fresh run — the far
more common path, and the one with no guard at all until now.

The 24-hour default is chosen to comfortably cover the legitimate
"interrupted, fixing the bench, resuming shortly" case, including an
overnight gap, while excluding sessions old enough that the operator has
almost certainly moved on.

## Scope

| Applies to                       | Notes                                            |
|----------------------------------|--------------------------------------------------|
| `power_cycle.py`, `reboot.py`    | the LOG023 resumable multi-iteration tests       |
| `function.resolve_session()`     | the shared decision point                        |
| `run_tests.sh`                   | passes `--resume` / `--resume-max-age` through   |
| Ansible orchestration            | non-interactive; flags only, never a prompt      |

Single-run tests with no iteration counter (`disk_test.sh`, `net_test.sh`,
`dev_detect.sh`) are out of scope — they have no session to resume.

## Implications

1. `resolve_session()` gains `max_age_hours` and `force_resume` parameters
   and returns an additional `skipped` list describing incomplete sessions
   passed over for age, so the caller can report them.
2. Session age is derived from `updated_at`, falling back to `started_at`,
   then to `meta.json`'s mtime — a session written by an older build
   without timestamps is still aged rather than treated as ageless.
3. The decision is never made interactively. FWK024 requires
   non-interactive operation under Ansible; a TTY prompt would hang an
   automated run. Age bounding plus an explicit banner gives the same
   protection without blocking.
4. A stale session is **skipped, not deleted or rewritten**. Its directory
   and `meta.json` remain untouched and it stays resumable via `--resume`,
   preserving FWK028's canonical record.
5. Operators no longer need to delete the output directory to guarantee a
   clean run; `--new-session` is the supported way, and the default already
   does the expected thing after a day.

## Verification

`src/python/resolve_session_unittest.py` covers the full decision matrix
over `resolve_session()`, with no GPIO, SSH, or DUT required:

```bash
cd src/python && python3 -m unittest resolve_session_unittest -v
```


| Case                                  | Expected                        |
|---------------------------------------|---------------------------------|
| incomplete session 2 h old            | resumes, `start_n = n + 1`      |
| incomplete session 50 h old           | new session, 1 skip reported    |
| 50 h old + `--resume`                 | resumes the old session         |
| fresh session + `--new-session`       | new session                     |
| `--resume-max-age 0`                  | never auto-resumes              |
| `--resume-max-age -1`                 | resumes at any age              |
| `meta.json` without timestamps        | ages by mtime, resumes if fresh |
| complete session (`n == m`)           | ignored, not reported as a skip |
| skipped session's `meta.json`         | unchanged on disk               |
| target mismatch (LOG025)              | still raises                    |
| explicit `--cycles` mismatch (BUG0041)| still raises                    |

Console verification: a dry run with a seeded stale session shows the
`NEW session` banner plus the skip warning; the same run with `--resume`
shows the `RESUMING` banner with the completed-cycle count.
