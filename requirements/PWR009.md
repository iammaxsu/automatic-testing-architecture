# PWR009 — Multi-Strategy DUT Shutdown

## Statement

`power_cycle.py` shall delegate every normal power-off action to a
`ShutdownCoordinator` object (`shutdown.py`) that tries the following methods
in priority order, stopping at the first that succeeds:

1. **SSH command** — issues `shutdown /s /t 5` via SSH, then waits for the
   DUT to go offline. Activated when `--ssh-user` is provided on the command
   line (or `SHUTDOWN_SSH_USER` is set in `config.py`).
2. **ATX soft press** — 0.5 s relay pulse (ACPI power button signal), then
   waits for DUT to go offline; for AT PSUs, calls `at_power_off()`.
3. **ATX force-off** — 5 s relay hold; applied automatically if the soft
   press times out (i.e. DUT still responds after `DEAD_TIMEOUT_SEC`).
4. **Time-based** — blind wait for `OFF_TIME_SEC` seconds; last resort when
   no relay is available.

Each cycle record written to `result.json` shall include a `shutdown_method`
field recording which method was used (`"ssh"`, `"atx"`, `"force"`, or
`"time"`).

## Rationale

A single inline ATX short press is insufficient for Windows DUTs: the ACPI
signal triggers a soft shutdown that can take 20-30 s or hang entirely.
Adding an SSH shutdown command allows Windows to close applications and shut
down gracefully before the relay acts, reducing HANG_SHUTDOWN verdicts. The
fallback chain (SSH -> ATX soft -> force-off -> time-based) ensures the test
can still proceed even when SSH is unavailable or the relay is not connected.

## Scope

`src/python/shutdown.py` (new module), `src/python/power_cycle.py`,
`src/python/config.py`.

## Implications

- `--ssh-user USERNAME` added to `power_cycle.py`; default empty (SSH method
  disabled). Set to the OS account used for SSH login on the DUT.
- `SHUTDOWN_SSH_USER = ""` added to `config.py` as the persisted default.
- `ShutdownCoordinator` is constructed once in `main()` and reused for every
  cycle, including warmup cycles.
- `shutdown_method` is recorded per-cycle in `result.json`.
- Force-off inside CRASH / NO_BOOT recovery paths (`_force_off()`) is
  intentionally kept as a direct relay call — those paths require immediate
  hard power-off regardless of shutdown strategy.
- Serial port method is reserved as a placeholder in `shutdown.py` for
  future expansion.
