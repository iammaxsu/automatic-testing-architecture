# PWR009 — Multi-Strategy DUT Shutdown

## Statement

`power_cycle.py` shall delegate every normal power-off action to a
`ShutdownCoordinator` object (`shutdown.py`) that tries the following methods
in priority order, stopping at the first that succeeds:

1. **SSH command** — issues the OS's immediate shutdown (`shutdown /s /t 0` on
   Windows, `sudo shutdown -h now` on Linux) via SSH, then waits for the
   DUT to go offline. Activated when `--ssh-user` is provided on the command
   line (or `SHUTDOWN_SSH_USER` is set in `config.py`).
2. **ATX soft press** — 0.5 s relay pulse (ACPI power button signal), then
   waits for DUT to go offline; for AT PSUs, calls `at_power_off()`.
3. **ATX force-off** — `ATX_LONG_PRESS_SEC` relay hold; applied automatically if the soft
   press times out (i.e. DUT still responds after `DEAD_TIMEOUT_SEC`).
4. **Time-based** — blind wait for `OFF_TIME_SEC` seconds; last resort when
   no relay is available.

Each cycle record written to `result.json` shall include a `shutdown_method`
field recording which method was used (`"ssh"`, `"atx"`, `"force"`, or
`"time"`).

## Rationale

A single inline ATX short press is insufficient for Windows DUTs: the ACPI
signal triggers a soft shutdown that can take 20-30 s or hang entirely.
Adding an SSH shutdown command allows Windows to close applications and shut
down gracefully before the relay acts, reducing HANG_SHUTDOWN verdicts. The
fallback chain (SSH -> ATX soft -> force-off -> time-based) ensures the test
can still proceed even when SSH is unavailable or the relay is not connected.

## Scope

`src/python/shutdown.py` (new module), `src/python/power_cycle.py`,
`src/python/config.py`.

## Implications

- `--ssh-user USERNAME` added to `power_cycle.py`; default empty (SSH method
  disabled). Set to the OS account used for SSH login on the DUT.
- `SHUTDOWN_SSH_USER = ""` added to `config.py` as the persisted default.
- `ShutdownCoordinator` is constructed once in `main()` and reused for every
  cycle, including warmup cycles.
- `shutdown_method` is recorded per-cycle in `result.json`.
- Force-off inside CRASH / NO_BOOT recovery paths (`_force_off()`) is
  intentionally kept as a direct relay call — those paths require immediate
  hard power-off regardless of shutdown strategy.
- Methods 2–4 are **commanded, not confirmed**. The relay is an output only, so
  a force-off the DUT ignored is indistinguishable from one that worked; only
  method 1 and the liveness poll produce evidence, and the poll cannot tell a
  powered-off DUT from one stopped at a screen with no network. `force_off_sec`
  therefore records the hold that was asked for and nothing about the outcome
  (BUG0066). Closing this needs a power-state input — BMC chassis status, a
  GPIO on the DUT's power LED, or a current sensor.
- A force-off following a cycle that already failed to boot is held for
  `ATX_FORCE_OFF_ESCALATE_SEC` (`--force-off-escalate`, 0 disables) rather than
  repeating an unverifiable action unchanged.
- The hold is `ATX_LONG_PRESS_SEC`, set from what a DUT was observed to obey
  rather than from the ATX spec's 4 s minimum: a DUT at the Windows Recovery
  screen ignored 5 s and powered off on 10 s (BUG0064).
- Both OSes' shutdown commands are immediate, so `shutdown_time_sec` measures
  the DUT rather than a delay the framework asked for (BUG0068). Because an
  immediate shutdown can outrun its own SSH session, a command that reports
  failure is not believed until the DUT is given a bounded window to go offline;
  only then does the method fall through to the relay.
- Serial port method is reserved as a placeholder in `shutdown.py` for
  future expansion.

## Verification

`src/python/shutdown_unittest.py` — both OS commands are immediate and neither
forces applications closed; an SSH command that reports failure while the DUT
does go offline is recorded as `ssh`; a genuine failure still falls through to
the relay; the confirm window is bounded by both `SSH_CONFIRM_DEATH_SEC` and
`DEAD_TIMEOUT_SEC`; a coordinator with no liveness checker does not guess.

`src/python/force_off_unittest.py` — the escalation, its disable switch, the
`--debug` path, and that a cycle record never claims an outcome the relay cannot
observe.

Code Review: confirm `power_cycle.py` imports `ShutdownCoordinator`, constructs
it in `main()` with `relay`, `checker`, `psu_type`, `ssh_user`, `ssh_host`,
`ssh_port`, `dead_timeout_sec`, and `time_based_delay_sec`, and calls
`shutdown_coord.request()` in place of the former inline power-off block in
`run_one_cycle()`. Confirm `result.json` includes `shutdown_method` on each
cycle record.
