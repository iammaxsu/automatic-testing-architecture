# PWR008 — Power Cycle Test Warmup and Initial-State Normalization

## Statement

`power_cycle.py` shall normalize the DUT state before beginning the counted test and shall support a configurable number of warmup cycles:

1. **Initial-state normalization**: Before any cycle (warmup or counted), if the DUT is reachable on the network, the script shall issue a force-off and wait `OFF_TIME_SEC` seconds. This guarantees the test always starts from a known powered-off state regardless of how the DUT was left (e.g. powered on after running `setup_dut.ps1`).

2. **Warmup cycles** (`--warmup N`, default 1): Before cycle 1 of N, the script shall run N initialization cycles. Warmup cycles execute the full power-on / liveness / power-off sequence but their verdicts are **not counted** in pass/fail totals and do **not** increment the consecutive-failure abort counter. Each warmup cycle is labeled `[WARMUP n/N]` in the log.

3. **Boot timeout CLI override** (`--boot-timeout SECONDS`, default 180): The DUT boot timeout shall be overridable on the command line. The default is raised from 120 s to 180 s to accommodate Windows boot time plus sshd service start.

4. Both `warmup_cycles` and `boot_timeout_sec` shall be recorded in the `config` section of `result.json`.

## Rationale

A freshly set-up DUT may be in any of three states when `power_cycle.py` is first invoked: powered on, powered off, or mid-boot. An ATX short press on an already-running machine triggers a soft shutdown rather than a power-on, causing the first liveness check to time out with NO_BOOT — a false failure. Warmup cycles absorb this state uncertainty so that the first counted cycle always begins from a clean, verified OFF state. For long runs (e.g. 1000 cycles) even one spurious NO_BOOT causes a misleading overall FAIL verdict; warmup eliminates this class of false positive.

## Scope

`src/python/power_cycle.py` and `src/python/config.py`.

## Implications

- Default warmup is 1 cycle; set `--warmup 0` to disable for scripted environments where the initial state is guaranteed.
- Warmup cycles increase total wall-clock time by approximately `(BOOT_TIME + ON_TIME + OFF_TIME) * warmup` seconds.
- The force-off at test start is skipped when liveness checks are disabled (`--no-check`).

## Verification

Automated Test: run `power_cycle.py --dry-run --warmup 2 --cycles 3 --no-check` and confirm the log shows `[WARMUP 1/2]` and `[WARMUP 2/2]` followed by `Cycle 1 / 3`; confirm warmup verdicts are not present in `result.json` cycles array.
