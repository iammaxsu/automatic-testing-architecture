# PWR002 — GPIO Relay Abstraction

## Statement

GPIO relay control shall be encapsulated in a dedicated `relay.py` module with the following properties:

- Supports active-low and active-high relay modules via `RELAY_ACTIVE_LOW` config flag (default: `True`, matching most RPi relay modules).
- Exposes `cleanup()` that de-energises the relay and releases the GPIO pin before exit.
- Degrades gracefully to dry-run mode when `RPi.GPIO` is not available (non-RPi development machines), logging all operations without touching hardware.
- GPIO pin number and addressing mode (`BOARD` or `BCM`) shall be configurable.

## Rationale

Coupling GPIO calls directly to the test logic prevents dry-run testing on non-RPi machines and makes unit testing impossible. A dedicated abstraction layer also ensures the relay is always de-energised on exit, regardless of how the script terminates.

## Scope

`src/python/relay.py`, `src/python/config.py`, `src/python/gpioclean.py`.

## Implications

- `gpioclean.py` must be usable as a standalone emergency tool to de-energise the relay without running the full test.
- All GPIO `output()` calls must be routed through `relay.py`; no direct `GPIO.output()` calls in `power_cycle.py`.
