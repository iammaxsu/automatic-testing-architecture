# SET006 — Dual-Layer Configuration: config.py as Default Reference

## Statement

Every configurable parameter in the Python test framework shall be accessible via
two layers, in the following override order (highest wins):

1. **CLI argument** — passed at invocation time; takes precedence over all defaults.
2. **config.py value** — the canonical default; read when no CLI argument is supplied.

`config.py` shall document every configurable parameter as a named constant with:
- its default value,
- a comment identifying the matching CLI flag (e.g., `# CLI: --boot-timeout`), and
- a brief inline explanation of the parameter's effect.

`config.py` shall contain **only plain constants and inline comments** — no
conditional logic, no function calls, no imports beyond the standard library.
It is a configuration file, not a module.

## Rationale

Users who run tests frequently learn the CLI flags. Users who run tests occasionally
— or who are setting up a new DUT — need a readable reference that shows every
knob and its default without reading source code. `config.py` fills both roles:

- **Experienced users** override at the command line without touching `config.py`.
- **Less-experienced users** edit `config.py` once to set site-specific defaults
  (GPIO pin, DUT IP, SSH user, cycle count) and then run scripts with no arguments.

Keeping the two layers explicit and documented avoids "magic defaults" that
surprise new operators.

## Scope

`src/python/config.py`; all Python scripts that import it (`power_cycle.py`,
`reboot.py`, `function.py`, and any future scripts added to `src/python/`).

## Implications

1. A new configurable parameter must be added to `config.py` **before or in the
   same commit** as the CLI argument that exposes it.
2. The `# CLI: --flag-name` comment in `config.py` is normative: it names the exact
   CLI flag that overrides the constant; if the flag is renamed the comment must
   be updated in the same commit.
3. Scripts shall use `default=config.CONSTANT` in `argparse.add_argument()` so that
   `--help` output always shows the current `config.py` default.
4. Parameters that are intentionally not exposed via CLI (e.g. internal timing
   constants like `ATX_SHORT_PRESS_SEC`) are exempt from the CLI comment
   requirement but must still appear in `config.py`.

## Verification

Code Review: confirm each CLI argument in `power_cycle.py` and `reboot.py` has a
matching constant in `config.py` with a `# CLI: --flag` comment; confirm `config.py`
contains no logic, only constants and comments.
