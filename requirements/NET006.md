# NET006 — iperf3 Throughput in Four Combinations

## Statement

For each interface, and for every speed that NET014 reports as `CONNECTABLE` and
that passed ICMP connectivity (NET005), throughput shall be measured with iperf3
in four combinations: TCP forward, TCP reverse, UDP forward, UDP reverse.

Each of the four combinations shall produce a per-interface, per-speed
measurement and verdict (PASS / FAIL / UNKNOWN, per NET008/NET009), recorded in
result.json and rendered in the report, so the operator can read the TCP and UDP
performance achieved at each connectable speed and see which combination, if
any, underperformed.

## Rationale

TCP and UDP exercise different parts of the stack; measuring both, in both
directions, at each connectable speed gives a complete per-speed performance
picture. Reporting the four combinations separately lets the operator localise a
throughput problem to a specific protocol/direction at a specific speed rather
than to the interface as a whole.

## Scope

All scripts and shared libraries in the framework.

## Implications

1. Throughput runs only for speeds that are connectable (NET014) and reachable
   (NET005); other speeds carry their link/connectivity verdict instead.
2. Each (interface, speed, combination) yields its own measurement and verdict.
3. TCP and UDP results are reported separately per speed, not collapsed into a
   single per-interface number.
4. Non-compliance must be corrected before merge.
