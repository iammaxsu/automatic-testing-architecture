# DET012 — Windows Hardware Baseline Verification

## Statement

A script `src/powershell/dev_detect.ps1` shall verify the hardware configuration of a Windows DUT against a golden reference at each startup. The script shall:

1. Check five hardware categories: CPU model, total memory (GB), USB PassMark loopback plug count, NIC model counts (all physical adapters), and storage model+bus counts.
2. On first run, write a golden reference file for each category under `logs/` beside the script.
3. On subsequent runs, compare the current values to the goldens; any deviation shall produce a `FAIL` verdict for that category.
4. Record an overall verdict (`PASS` / `FAIL`) and write:
   - A per-run combined log: `logs/<count>_<date2>_<PASS|FAIL>.log`
   - An appended summary log: `logs/summary.log`
5. Include best-effort PCIe link information (Gen, width, approximate GB/s) for NIC and NVMe storage.
6. Be runnable by Task Scheduler as `SYSTEM` at startup (registered via `setup_dut.ps1 -DevDetectScript <path>`).
7. Dot-source `function.ps1` and declare `$_script_ver`.

## Rationale

Power cycle and reboot tests may cause hardware enumeration failures that are invisible to a simple liveness check. Running device detection at each startup and comparing against a golden baseline provides an automated signal when a peripheral drops off after a power event.

## Scope

`src/powershell/dev_detect.ps1`.

## Implications

- The golden files are initialised on the first run; ensure the DUT is fully configured (all test peripherals connected) before the first run.
- USB PassMark loopback plug detection requires the PassMark USB3.0 Loopback Plug to be physically connected and its driver installed.
- PCIe link info is best-effort; not all drivers expose `DEVPKEY_PciDevice_CurrentLink*` properties.
- Log files accumulate indefinitely; implement rotation separately if storage space is a concern.

## Verification

Code Review: confirm five check functions are present; confirm golden initialisation on first run and comparison on subsequent runs; confirm per-run log and summary log are written; confirm `function.ps1` is dot-sourced and version-checked; confirm SYSTEM compatibility (no user-profile paths).
