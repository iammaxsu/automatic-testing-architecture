# LOG024 — Composite (Multi-Test) Run Log Separation

## Statement

A composite run that combines a continuous-mode driver with a
discrete-mode test on the DUT (e.g. `power_cycle` + `dev_detect`, or
`reboot` + `dev_detect`) shall produce both artefact kinds, co-located in
the same session directory and sharing one `session_id` and `n`/`m`
(LOG023):

1. A continuous-mode `<driver>_<session>.log` + `<driver>_<session>.result.json`
   for the power/boot cycling itself (produced by the driver on the
   control node).
2. One discrete-mode `dev_detect_<n>_of_<m>_<ts>_<result>.log` per cycle,
   where `<n>` is the cycle index supplied by the driver (produced by
   `dev_detect` on the DUT).

The discrete logs produced on the DUT shall be collected into the driver
session directory on the control node.

## Rationale

Reliability testing frequently pairs power/boot cycling with a
per-boot component-detection check: each cycle powers the DUT, the DUT
auto-runs `dev_detect` on boot, and the cycle then powers down. Keeping
the cycling record (continuous) separate from the per-boot detection
records (discrete) — while sharing one session identity — gives a clean,
queryable history: "on cycle 487 the boot succeeded but `dev_detect`
reported a missing NIC."

## Scope

`src/python/power_cycle.py` (and future `reboot`), `src/python/`
orchestration; `src/powershell/dev_detect.ps1`,
`src/bash-shell/dev_detect.sh`.

## Implications (architecture — phased)

This requirement spans two machines and is implemented in phases:

- **Phase 1 (LOG023, implemented separately):** single-machine session +
  resume for the continuous-mode driver. No cross-machine coordination.
- **Phase 2 (this requirement):** the driver must
  1. share the cycle index `n` with the DUT so `dev_detect`'s
     `<n>_of_<m>` aligns with the driver's cycle number (e.g. pass `n`
     over the existing SSH channel, or write it to a DUT-side file), and
  2. collect each cycle's `dev_detect` log from the DUT back to the
     control-node session directory (e.g. `scp` over the SSH channel the
     driver already opens for shutdown, per PWR009).

  The control node already establishes an SSH session to the DUT for
  graceful shutdown (PWR009); the same channel can carry the index and
  retrieve the log, so no new transport is required.

## Verification

Code Review: confirm a composite run yields a single continuous
`<driver>_<session>` pair plus per-cycle `dev_detect_<n>_of_<m>_*` logs
in one directory under one `session_id`; confirm the `dev_detect` index
matches the driver's cycle number.
