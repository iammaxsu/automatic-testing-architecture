# PWR005 — Structured result.json Output (LOG015 Compliance)

## Statement

The power cycle test shall emit a `power_cycle_<timestamp>.result.json` file conforming to the LOG015 schema. The file shall contain:

- Top-level metadata: `test_name`, `started_at`, `ended_at`, `config` (all test parameters).
- `cycles` array: one object per completed cycle, with fields `n`, `t_start`, `t_power_on`, `t_alive`, `boot_time_sec`, `t_power_off`, `t_dead`, `shutdown_time_sec`, `verdict`, `notes`.
- `summary` object: `cycles_target`, `total_ran`, `pass`, `fail`, `fail_breakdown` (count per verdict type).
- `overall_verdict`: `PASS`, `FAIL`, or `NO_DATA`.

The file shall be written **atomically after every cycle** (write to `.tmp` then rename) so partial results are available if the test is interrupted.

## Rationale

Conforms to FWK028: `result.json` is the canonical machine-readable record from which all human-readable views (HTML report, summary table) are rendered. Writing after every cycle preserves data on unexpected termination.

## Scope

`src/python/power_cycle.py`, `src/python/function.py`.

## Implications

- The HTML report (PWR006) must be generated from `result.json`, not from in-memory state.
- Timestamps shall be ISO-8601 UTC strings.

## Verification

Code Review: confirm JSON is written atomically after each cycle; confirm all required fields are present; confirm `overall_verdict` roll-up logic.
