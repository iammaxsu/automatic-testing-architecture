# FWK034 — Zero-Argument Usability for Co-Deployed Scripts

## Statement

Scripts that are always deployed together in the same directory shall be
usable with **no arguments** for the common case. Specifically:

1. A setup or configuration script shall auto-detect sibling scripts
   (scripts in the same directory as itself) and act on them without
   requiring the operator to supply explicit paths.
2. An explicitly supplied argument shall always override auto-detection.
3. If a sibling is not found and no explicit path was given, the
   corresponding step shall be **skipped silently** (not an error), with
   a brief explanatory message.
4. Parameters for path overrides shall remain available for non-standard
   layouts, but shall never be required for the common deployment layout.

## Rationale

Scripts in this framework are deployed as a unit — by USB copy, `scp`, or
Ansible — so co-located scripts are the norm, not the exception.
Requiring the operator to type full paths to files that are sitting right
next to the script they are already running is unnecessary friction.

Lesson learned from BUG0026: the single most common operator error during
the initial DUT setup was running `setup_dut.ps1` without `-RebootScript`,
leaving the `DUT-Reboot` Task Scheduler task unregistered. The reboot test
then silently failed after the first cycle because no Task Scheduler trigger
existed to continue it. The operator had no indication that the task was
missing until the test stopped unexpectedly.

Making the zero-argument path complete and correct eliminates an entire
class of silent misconfiguration.

## Scope

`src/powershell/setup_dut.ps1` — auto-detects `reboot.ps1` and
`dev_detect.ps1` in its own directory (`$_script_root`).

Any future setup or installer script that references companion scripts
that ship in the same deployment package.

## Implications

1. Auto-detection uses the script's own directory (`$PSScriptRoot` /
   `$_script_root` in PowerShell; `__file__` parent in Python), not the
   current working directory, because operators may invoke scripts from
   any working directory.
2. Auto-detection runs **after** the privilege check (FWK033) and
   **before** the first step that could use the detected paths.
3. When a sibling is auto-detected, the script shall log the resolved
   absolute path at a low-visibility level (e.g. `DarkGray`) so the
   operator can confirm which file is being used without the output
   becoming noisy.
4. When a sibling is not found (and no explicit path given), the skip
   message shall explain how to supply the path explicitly — this is the
   only case where a parameter becomes necessary.
5. This principle does not apply to scripts that are intentionally
   distributed separately (e.g. a Python renderer that ships in a
   different package); those may still require explicit configuration.

## Verification

- Confirm an explicit `-RebootScript` path overrides auto-detection.
- Confirm that missing siblings produce a skip (not an error).
