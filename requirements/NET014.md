# NET014 — Per-Speed Link Establishment Verification and Reporting

## Statement

For each interface, and for every link speed the interface advertises as
supported (NET004), net_test.sh shall verify whether a link can actually be
established at that speed before attempting any IPv4/IPv6 connectivity (NET005)
or throughput (NET006) test:

1. Configure the interface to the candidate speed (forced full-duplex where the
   driver permits, otherwise via auto-negotiation constrained to that speed).
2. Wait up to a configurable timeout (default 30 s) for the link to reach the
   operational UP state at the requested speed.
3. Record a per-interface, per-speed link verdict:
   - `CONNECTABLE` — link reached UP at the requested speed within the timeout.
   - `NOT-CONNECTABLE` — link never came up, or came up at a different speed,
     within the timeout (e.g. the NIC reports the speed as advertised but the
     link drops when that speed is forced).

The link verdict shall be written to result.json as the canonical record and
rendered in the HTML report as a clearly-labelled per-speed status, so the
operator can read directly which speeds connect and which do not, per interface.

A speed that is `NOT-CONNECTABLE` shall be reported as such and skipped for the
IPv4/IPv6 and throughput stages — it shall not be silently dropped, and its
absence from later stages shall be explained by this verdict rather than left
ambiguous.

## Rationale

Some NICs advertise a speed as supported yet fail to establish a link when that
speed is forced — observed on an Intel I219-V, which links normally under
auto-negotiation but goes Disconnected when forced to 1.0 Gbps Full Duplex.
This is a property of the NIC/switch link, not of the test logic. Without an
explicit per-speed link verdict, this failure is indistinguishable from a
throughput failure or from a speed that was never tested: the report shows an
empty or missing throughput result with no stated cause.

NET014 makes "can this interface link at this speed at all?" a first-class,
explicitly-reported result, distinct from the throughput verdict (NET008/NET009).
This lets the operator immediately localise the problem to the link layer
(NIC, switch port, or cable) versus the throughput layer.

## Scope

| Applies to            | Notes                                             |
|-----------------------|---------------------------------------------------|
| net_test.sh           | Per-interface, per-advertised-speed link check.   |
| result.json           | Canonical per-speed link verdict.                 |
| net_test report (HTML)| Renders per-speed link status, per interface.     |

NICs excluded by NET011/NET012 (config exclusion or SSH lifeline) are out of
scope and are never reconfigured.

## Implications

1. The link verdict (`CONNECTABLE` / `NOT-CONNECTABLE`) is recorded per
   interface per advertised speed, not merged into the throughput verdict.
2. The link-up timeout is a config parameter (default 30 s).
3. A `NOT-CONNECTABLE` speed produces an explicit reported row; IPv4/IPv6 and
   throughput stages for that speed are marked skipped-due-to-no-link, not blank.
4. After all speeds for an interface are tested, the interface shall be restored
   to auto-negotiation so the link is left in a working state.
5. Non-compliance must be corrected before merge.

## Verification

Automated Test — drive an interface whose forced speed drops the link and
confirm the per-speed link verdict is `NOT-CONNECTABLE` in result.json and is
rendered as such in the report, while an auto-negotiable speed is `CONNECTABLE`.
