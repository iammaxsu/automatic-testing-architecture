# NET019 — NIC Selection by MAC (Include / Exclude)

## Statement

The framework shall let operators select which NICs participate in the network
test **by MAC address**, through two configuration lists that behave
identically across every language implementation of the network test
(`config.sh` / `net_test.sh`, `config.ps1` / `net_test.ps1`, and any future
Python implementation):

| Config key | Meaning |
|------------|---------|
| `_net_include_macs` | **Whitelist.** When non-empty, **only** NICs whose MAC matches an entry are tested. When empty, all NICs are candidates (subject to the vendor filter and to the exclusions below). |
| `_net_exclude_macs` | **Blacklist.** A NIC whose MAC matches an entry is never tested, regardless of the include list or vendor filter. |

MAC matching shall be **case-insensitive** and accept both colon
(`AA:BB:CC:DD:EE:FF`) and hyphen (`AA-BB-CC-DD-EE-FF`) separators. Each list
accepts multiple entries separated by comma, semicolon, or whitespace.

### Precedence (highest wins)

1. **NET012 lifeline / session protection** — the NIC carrying the active
   inbound management session (and any `_net_exclude_macs` management NIC) is
   **always** excluded, *even if its MAC also appears in `_net_include_macs`*.
   Positive selection must never be able to override the safety net that keeps
   the operator's SSH/RDP connection alive.
2. **Exclude** — a MAC present in both lists is excluded.
3. **Include** — when `_net_include_macs` is non-empty, NICs not in it are not
   tested.
4. **Vendor filter / default** — remaining NICs are tested as today.

### CLI overrides

Each implementation shall provide CLI overrides equivalent to its existing
name-based `--skip` / `-Skip` (NET011): `--include-mac` / `--exclude-mac`
(Bash) and `-IncludeMac` / `-ExcludeMac` (PowerShell). CLI values override the
corresponding config list for that run.

### Reporting

NICs removed by an exclude, or omitted because they are not in a non-empty
include list, shall appear as **SKIPPED** rows in the summary log and in
`result.json` (consistent with NET011), with the reason recorded
(`excluded-mac`, `not-in-include-mac`, or `lifeline`).

## Rationale

Today the capability is split and asymmetric:

- NET011 defines only **name-based** exclude (`--skip` / `-Skip`), implemented
  in both Bash and PowerShell.
- NET012 defines **MAC-based** exclude (`_net_exclude_macs`) for lifeline
  protection — but it is implemented **only in PowerShell** (`config.ps1`);
  `config.sh` has no equivalent, so the same management NIC cannot be pinned on
  a Linux DUT. This is exactly the cross-language drift FWK036 is meant to
  prevent.
- There is **no positive selection** at all: an operator who wants to test only
  one specific NIC (by MAC, which is stable across reboots and OS reinstalls,
  unlike interface names) cannot express that intent.

A MAC is the most stable, OS-independent NIC identity, so MAC-based
include/exclude is the right primitive for persistent per-DUT policy in
unattended / Ansible-driven runs.

## Scope

The network test and its shared libraries in every language implementation:
`src/bash-shell/` (`config.sh`, `net_test.sh`), `src/powershell/`
(`config.ps1`, `net_test.ps1`), and any future `src/python/` network test.
MAC-based exclude must be **added to the Bash side**, which currently lacks it.

## Implications

1. `config.sh` gains `_net_include_macs` and `_net_exclude_macs` with the same
   names, parsing rules, and semantics as `config.ps1`.
2. `config.ps1` gains `_net_include_macs` (it already has `_net_exclude_macs`).
3. Both `net_test.sh` and `net_test.ps1` apply the precedence order above, with
   NET012 lifeline protection unconditionally winning over any include entry.
4. A MAC listed in `_net_include_macs` that is also the lifeline NIC is still
   excluded; the run logs a clear warning that the requested NIC was protected.
5. Non-compliance must be corrected before merge.

## Verification

Automated Test: with a multi-NIC DUT, confirm that (a) a non-empty
`_net_include_macs` tests only the listed MAC(s); (b) `_net_exclude_macs`
removes the listed MAC(s); (c) a MAC in both lists is excluded; (d) the
lifeline NIC is excluded even when its MAC is placed in `_net_include_macs`;
(e) the Bash and PowerShell implementations produce equivalent SKIPPED
rows and reasons for the same configuration.
