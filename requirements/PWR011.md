# PWR011 — DUT-Local Reboot Test (`reboot.ps1`)

## Statement

`reboot.ps1` shall implement a self-contained reboot endurance test that runs entirely
on the DUT without requiring a control node:

1. **Session start** (`--cycles N`): When invoked manually with `--cycles N`, the script
   shall create a session file (`logs/reboot_session.json`) recording
   `session_id`, `m` (target cycle count), `n = 0`, and `status = "running"`,
   then immediately issue `Restart-Computer`.

2. **Cycle recording**: On each subsequent boot, Task Scheduler invokes `reboot.ps1`
   automatically. The script shall:
   - Read the session file; if `status != "running"` or `n >= m`, exit without action
     (normal boot, no test in progress).
   - Record the cycle: `n++`, write a one-line entry to the per-session log file.
   - Verdict: **PASS** = `reboot.ps1` was successfully invoked by Task Scheduler
     (i.e. the DUT completed POST and booted far enough to run the script).
   - If `n < m`: issue `Restart-Computer` after a configurable settle delay
     (`REBOOT_SETTLE_SEC`, default 30 s).
   - If `n >= m`: set `status = "complete"` in the session file and stop.

3. **Log files** (LOG022 / LOG023 naming):
   - Per-session log: `logs/reboot_<session_id>.log`
   - Session state:   `logs/reboot_session.json`
   - `session_id` uses ISO-8601 basic format (`YYYYMMDDTHHmmss`, LOG022).

4. **Resume**: If `reboot.ps1` is invoked manually while a session with
   `status = "running"` and `n < m` already exists, it shall resume from `n + 1`
   under the same `session_id` (same log files). `--new-session` forces a fresh start.

5. **Task Scheduler registration**: `setup_dut.ps1` shall register `reboot.ps1` as a
   Task Scheduler task that runs at every system startup (as SYSTEM, with highest
   privileges). This mirrors the registration already performed for `dev_detect.ps1`.

## Rationale

Power-off/on cycling (controlled externally via relay) and software reboot represent
different hardware failure modes. A DUT can pass 1000 power cycles yet fail on the
100th software reboot due to a driver hang or filesystem corruption. Running the reboot
test on the DUT itself means no control-node infrastructure is required, making it
usable in environments where only the DUT is present.

## Scope

`src/powershell/reboot.ps1` (new); `src/powershell/setup_dut.ps1` (updated to
register the Task Scheduler task).

## Implications

1. `reboot.ps1` is safe to leave registered in Task Scheduler permanently: it exits
   immediately if no `status = "running"` session exists.
2. A test started manually (`reboot.ps1 --cycles 1000`) will reboot the DUT
   immediately — warn the user in the script header.
3. The settle delay (`REBOOT_SETTLE_SEC`) prevents immediately re-rebooting before
   the OS finishes writing logs from the previous boot.
4. `dev_detect.ps1` also runs at startup (registered separately); the two scripts run
   independently and each produce their own log.

## Verification

Automated Test: run `reboot.ps1 --cycles 3 --dry-run` (dry-run mode skips actual
`Restart-Computer`) and confirm:
- `reboot_session.json` is created with `m=3, n=0, status="running"`.
- Manually calling `reboot.ps1` (simulating the 3 Task Scheduler triggers) increments
  `n` to 3 and sets `status="complete"`.
- Log file `reboot_<session_id>.log` contains 3 cycle entries.
