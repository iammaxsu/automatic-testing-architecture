# FWK028 — Machine-Readable Canonical Form First

## Statement

Every test artefact shall have a single machine-readable canonical form as its
source of truth. Human-readable views (HTML reports, status dashboards,
progress summaries) shall be **rendered** from the canonical form and never
edited directly. Bidirectional dependency between canonical and derived forms
is prohibited.

## Rationale

When two representations of the same data can be edited independently, they
inevitably diverge. Designating one form as canonical eliminates ambiguity:
there is always one authoritative answer to "what did the test produce?", and
all derived views can be regenerated on demand.

This principle also enables post-hoc analysis: if the report renderer is
improved after a test run, the canonical JSON can be re-rendered without
re-running the test.

## Scope

| Artefact type            | Canonical form                     | Derived form(s)                   |
|--------------------------|------------------------------------|-----------------------------------|
| Test result              | `<test>_<session>.result.json`     | `<test>_report_<session>.html`    |
| Requirement catalogue    | `requirements/**/*.md` (frontmatter) | `STATUS.md`, `STATUS.html`      |
| Bug catalogue            | `bugs/**/*.md` (frontmatter)       | bug indexes, traceability tables  |
| Session progress         | `*_session.json`                   | `*_STATUS.txt`, progress popups   |

## Implications

1. `result.json` is written atomically (write to `.tmp`, then rename) after
   every cycle so that a crash mid-write never corrupts the last good record.
2. HTML reports and `STATUS.md` / `STATUS.html` are re-generated from JSON /
   Markdown sources; they are never hand-edited.
3. `make stats` (or the equivalent Python invocation) regenerates all derived
   views. It shall be run after any non-trivial change to `requirements/` or
   `bugs/` and committed in the same commit.
4. Tooling that reads result data (report renderers, CI dashboards, analysis
   scripts) must target the canonical JSON schema, not the HTML report.
5. The canonical JSON schema version is recorded in every `result.json` as
   `schema_version`; renderers must handle schema evolution gracefully.

## Verification

- Code review confirms no derived file is written directly; all paths go
  through the canonical write helpers (`write_result_json`, `Write-ResultJson`,
  `write_json`).
- `make stats` re-generates `STATUS.md` and `STATUS.html` cleanly from
  `requirements/` and `bugs/` without manual edits.
