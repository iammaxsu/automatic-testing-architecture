# LOG025 — DUT-First Session Directory Layout

## Statement

Every continuous-mode session-based test (`power_cycle.py`, `reboot.py`, and any
future test built on `function.resolve_session()`) shall locate its session
directory at:

```
<base_dir>/<dut_id>/<test>_<session_id>/
```

where `<base_dir>` is the value of `--out` (or `--report` for HTML output, see
PWR006), `<dut_id>` is a filesystem-safe slug (`function.dut_slug()`) derived
from `--dut-id` if given, else from `--host`, and `<session_id>` is the
ISO-8601-basic session start time (LOG022/LOG023).

Each session directory is self-contained and holds:

- `meta.json` — the LOG023 session-state record (`session_id`, `test`, `m`,
  `n`, `status`, `started_at`, `updated_at`), plus `dut_id` and a `target`
  object recording the identity fields that must match for a resume to be
  valid (`host`, `port`, `ssh_user`, and any test-specific fields such as
  `type`).
- `<test>_<session_id>.log`
- `<test>_<session_id>.result.json`
- `<test>_<session_id>.report.html` (or `<test>_report_<session_id>.html`,
  matching each script's existing filename convention — this requirement only
  relocates the directory, it does not rename existing artefact files)

On startup, session resolution (`function.resolve_session()`) scans
`<base_dir>/<dut_id>/` for a `<test>_*` directory whose `meta.json` has
`status == "running"` and `n < m`; if found (and `--new-session` is not
given), that session resumes. If the found session's `target` does not match
the current run's target identity, the run aborts with a
`SessionTargetMismatch` error rather than silently resuming the wrong DUT's
session or corrupting its state.

## Rationale

Before this requirement, the LOG023 session-state file
(`<test>_session.json`) lived directly under `--out` with a fixed name, and
log/result filenames were disambiguated only by `session_id` (a
to-the-second timestamp). This meant:

1. Two concurrent runs against **different DUTs** sharing the same `--out`
   directory raced on the same session-state file — one process could read,
   resume, and overwrite the other's bookkeeping mid-run.
2. If two such runs happened to start within the same second, their
   `session_id` collided too, so they raced on the **same log and result
   files** (BUG0035 exposed a related but distinct failure mode: a single
   process's own atomic write being interrupted by external interference).
3. There was no way to ask "show me everything that has ever run against
   this DUT" without grepping filenames across a flat directory.

`power_cycle.py` had already grown an ad-hoc `target` mismatch guard
(host/port/ssh_user/type) to catch the worst case of (1) at the single-file
level. Making the DUT identity part of the **path** rather than just a guard
inside one shared file removes the race entirely: two DUTs (or two
`--dut-id` values) physically cannot contend for the same directory, and an
operator can browse `logs/<dut_id>/` to see one machine's full test history.
Nesting the session under its own directory (rather than flattening
`<dut_id>_<test>_<session_id>.*` filenames) also makes each run trivially
self-contained — copy, archive, or delete one folder and you have/remove
exactly one test's artefacts, with FWK028's canonical `meta.json` /
`result.json` always alongside the rendered `.log` / `.report.html` they
came from.

`<dut_id>` deliberately defaults to `--host` but is independently
overridable via `--dut-id`, because an IP address is not a stable hardware
identity — DHCP can reassign it across reboots, and a decommissioned DUT's
IP can be reused by an unrelated unit. An operator who wants one continuous
history for a specific physical machine, independent of its current IP,
should pass `--dut-id` explicitly (e.g. an asset tag or serial number); this
requirement only mandates the directory layout and the safe default, not
which value operators use as the identity.

## Scope

`src/python/function.py` (`dut_slug()`, `resolve_session()`,
`SessionTargetMismatch`), `src/python/power_cycle.py`,
`src/python/reboot.py`.

## Implications

1. `--dut-id ID` added to both scripts; default `None` (falls back to a
   slugified `--host`).
2. `function.resolve_session(base_dir, test, dut_id, target, requested_m,
   new_session)` is the single shared implementation of session
   resolution/creation; both scripts call it instead of hand-rolling the
   LOG023 read/resume/create logic independently.
3. `function.dut_slug()` replaces filesystem-unsafe characters
   (anything outside `[A-Za-z0-9._-]`) with `_`; an empty/missing value
   slugs to `"unknown-dut"`.
4. A target mismatch on a candidate resume raises
   `function.SessionTargetMismatch`; callers catch it, log an error
   matching the prior single-file guard's wording, and exit non-zero
   instead of resuming.
5. This requirement changes *where* existing LOG017/LOG023 artefacts live,
   not their filenames or internal schema — `meta.json` is the renamed,
   relocated equivalent of the former `<test>_session.json`, with the same
   fields plus `dut_id`.
6. Not retroactive: pre-existing flat `<out>/<test>_session.json` /
   `<out>/<test>_<session_id>.*` layouts from before this change are not
   auto-migrated. A `--new-session` run after upgrading simply starts fresh
   under the new layout; an in-flight session interrupted before the
   upgrade should be resumed (old code) or restarted (`--new-session`)
   before upgrading the binary.

## Verification

Automated Test:
- Run `power_cycle.py`/`reboot.py --dry-run --new-session --out DIR --host
  A` and `--host B` against the same `DIR`; confirm both complete without
  error and produce `DIR/A/...` and `DIR/B/...` independently.
- Interrupt a run at `--host A`, rerun without `--new-session` under a
  different `--ssh-user`; confirm `SessionTargetMismatch` is raised and the
  run aborts with a clear error rather than resuming.
- Interrupt and resume normally (same target); confirm the same
  `session_id` and directory are reused and `meta.json`'s `n` continues
  rather than restarting.
