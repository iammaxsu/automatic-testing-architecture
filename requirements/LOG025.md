# LOG025 — Per-DUT Log Directory

## Statement

Test output for a given device under test (DUT) shall be written under a
per-DUT subdirectory of `logs/`, named by the DUT's address or hostname:
`logs/<dut>/…`. Combined with the per-session directory (LOG017, LOG023),
the full path for a run is `logs/<dut>/<session_id>/`. A run shall never
overwrite the output of a previous run, whether against the same DUT
(distinguished by `session_id`) or a different DUT (distinguished by
`<dut>`).

## Rationale

With a single flat `logs/` directory (LOG001/LOG002), a second run
overwrites the first, so results cannot be compared over time, and runs
against multiple DUTs are indistinguishable. Bench and lab setups
routinely test several DUTs and re-run the same suite; the output layout
must keep those results separate and non-destructive by construction, not
by operator discipline.

## Scope

| Applies to | `<dut>` value |
|------------|---------------|
| Out-of-band BMC/IPMI tests (control node) | the BMC host/IP under test |
| DUT-side tests fetched by Ansible | the DUT `inventory_hostname` / `ansible_host` |

The `<dut>` component shall be filesystem-safe (characters such as `:` and
`/`, e.g. in IPv6 literals, replaced with `_`).

## Implications

1. Runners build the output directory as `logs/<dut>/<session_id>/` before
   invoking the test, and pass it as the output location (e.g. Robot
   Framework `-d`, or a script's `--out`).
2. `<session_id>` is the ISO 8601 basic start time `YYYYMMDDTHHmmss`
   (LOG023), so repeated runs against one DUT land in sibling directories.
3. Existing per-session artefact names (LOG017) are unchanged; only their
   parent directory gains the `<dut>` and `<session_id>` levels.

## Verification

Automated Test: run a suite twice against the same `<dut>` and once against
a second `<dut>`; assert three distinct `logs/<dut>/<session_id>/`
directories exist and no file was overwritten.
