# SET007 — Linux DUT Pre-test Bootstrap Script

## Statement

A script `src/bash-shell/setup_dut.sh` shall perform all one-time manual steps
required to prepare a freshly-installed Ubuntu DUT for automated testing. The
script shall:

1. Check for root privileges as its first executable action (FWK033); if not
   root, print that nothing has been changed and exit non-zero.
2. Install and enable `OpenSSH Server (sshd)`, startup enabled.
3. If `ufw` is active, allow inbound SSH (TCP 22); leave ICMP echo alone
   (Ubuntu's default `ufw` rules already permit ping).
4. Establish passwordless SSH authorization for the Pi controller, idempotently
   and with zero-argument auto-detection (FWK034):
   - **Test user** is auto-detected when `--test-user` is omitted: the sudo
     invoker (`$SUDO_USER`), else the first regular human account
     (UID 1000-59999 with a `/home` directory).
   - **Pi public key** is resolved from, in priority order: `--pi-key` /
     `--pi-key-file`; a single `*.pub` file deployed next to the script; an
     interactive paste prompt when run on a terminal.
   - **Already-authorized detection**: if the resolved key is already in the
     user's `authorized_keys`, or if no key was supplied/found but the account
     already has authorized keys, the step is skipped and the script continues.
     Otherwise the resolved key is appended, creating `~/.ssh` and
     `authorized_keys` with the correct ownership and permissions (`700`/`600`).
5. Grant `--test-user` `NOPASSWD` sudo for `shutdown`, `reboot`, and `poweroff`
   via a dedicated file under `/etc/sudoers.d/`, validated with `visudo -cf`
   before installation.
6. Mask the `sleep.target`, `suspend.target`, `hibernate.target`, and
   `hybrid-sleep.target` systemd targets, and write
   `/etc/systemd/logind.conf.d/99-automatic-testing.conf` (a logind drop-in file)
   containing: `HandleLidSwitch*=ignore`, `HandleSuspendKey=ignore`,
   `HandleHibernateKey=ignore`, `IdleAction=ignore`,
   `HandlePowerKey=poweroff`, `HandlePowerKeyLongPress=poweroff`.
   The drop-in takes precedence over `/etc/systemd/logind.conf` and is fully
   reversible: `sudo rm <dropin> && sudo systemctl restart systemd-logind`.
   Any keys previously written directly into `/etc/systemd/logind.conf` by
   earlier versions of this script are cleaned up automatically.
7. If `unattended-upgrades` is installed, set
   `Unattended-Upgrade::Automatic-Reboot "false"`.
8. (Optional, via `--dev-detect-script`, auto-detected next to this script per
   FWK034) Register a systemd oneshot service (`dev-detect.service`,
   `WantedBy=multi-user.target`) to run `dev_detect.sh` as root a configurable
   delay after boot (default 30 s, via `ExecStartPre=sleep`). The unit name
   matches what `autorun_service_name_for("dev_detect.sh")` in `function.sh`
   derives, so `dev_detect.sh`'s own `autorun_setup()` call detects the service
   as already installed and skips redundant re-registration. Any obsolete
   `dut-dev-detect.{service,timer}` units from prior versions are cleaned up.
9. Ensure Python 3 is installed and download `report.py` alongside the script
   for local HTML report rendering.

The script shall be idempotent (safe to run multiple times) and declare its
own version with `_script_ver`.

## Rationale

This is the Linux counterpart of `setup_dut.ps1` (SET005): SSH and ping
accessibility, passwordless authentication, and privileged shutdown/reboot
commands are prerequisites for all RPi-driven liveness checks and lifecycle
control (`power_cycle.py`, `reboot.py`, `shutdown.py`). Without it, a freshly
imaged Ubuntu DUT has none of these in place, and every SSH call from the Pi
made with `BatchMode=yes` (FUN007/function.py) fails immediately with exit
255 — surfacing as a misleading `DUT OS detected: windows (uname -s exit 255)`
log line and `notify_dut`/health-check failures even though the DUT is
reachable via ping.

## Scope

`src/bash-shell/setup_dut.sh`.

## Implications

- This script must be run once manually (physical console, or an existing
  password-based SSH session) before any `BatchMode=yes` automated test can
  begin — the same chicken-and-egg bootstrap step as SET005.
- The Pi controller's public key (`cat ~/.ssh/id_ed25519.pub` on the Pi) is
  installed for passwordless SSH. It may be supplied explicitly
  (`--pi-key`/`--pi-key-file`) or auto-detected from a sibling `*.pub` file or
  an interactive paste; without any of these, SSH-based shutdown/reboot and OS
  detection (`function.py`: `detect_dut_os`, `notify_dut`) fail with exit 255.
  An already-authorized DUT is detected and the step is skipped, so re-running
  the script after the key is in place is a safe no-op.
- `shutdown.py`'s SSH method and `reboot.py` (with `--dut-os linux`) issue
  `sudo shutdown -h now` / `sudo reboot` non-interactively; without the
  `NOPASSWD` sudoers entry from step 5 these hang waiting for a password that
  will never arrive.
- Masking sleep/suspend/hibernate targets (step 6) prevents the DUT from
  entering a low-power state that would falsely register as a `CRASH`
  (PWR001) during `ON_TIME`. `HandlePowerKey=poweroff` in the logind drop-in
  makes logind handle the ATX short-press directly (kernel → logind → poweroff)
  instead of delegating to the GNOME session manager's interactive shutdown
  dialog, which times out and causes `HANG_SHUTDOWN` in `power_cycle.py`.
  To restore GNOME's default behavior after testing:
  `sudo rm /etc/systemd/logind.conf.d/99-automatic-testing.conf && sudo systemctl restart systemd-logind`.
- The sudoers file and systemd unit created by this script use fixed names
  (`/etc/sudoers.d/99-automatic-testing-<user>`, `dev-detect.service`) to
  enable idempotent re-registration. The unit name is shared with
  `dev_detect.sh`'s own `autorun_setup()` to prevent double-installation.
