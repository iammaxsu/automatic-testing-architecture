# PWR007 — Safety Controls: Consecutive Fail Abort and Graceful Stop

## Statement

The power cycle test shall implement two safety controls:

**1. Consecutive failure abort**
If the number of consecutive failed cycles reaches `MAX_CONSECUTIVE_FAILS` (default: 3, configurable in `config.py`), the test shall stop immediately, log the reason, and write the final `result.json` and HTML report. Setting `MAX_CONSECUTIVE_FAILS = 0` disables this control.

**2. SIGINT graceful stop (Ctrl-C)**
On receiving SIGINT, the test shall set a stop flag and finish the current cycle normally before exiting. It shall not abort mid-cycle, which could leave the relay energised (DUT stuck on or off). The final `result.json` and HTML report shall be written before the process exits.

In both cases, `relay.cleanup()` shall always be called via the `finally` block to de-energise the relay.

## Rationale

Without a consecutive-fail abort, a DUT that fails to boot will occupy the test bench for hours (e.g. 997 remaining cycles × 120 s boot timeout = 33 hours) with no diagnostic value. Graceful SIGINT handling prevents the relay from being left in an energised state, which could leave the DUT permanently powered on or off.

## Scope

`src/python/power_cycle.py`.

## Implications

- Hard-killing the process (`SIGKILL`) bypasses graceful stop; operators must use `gpioclean.py` to recover the relay state manually in that case.
- The HTML report is regenerated on each exit path so the report always reflects the actual cycles that ran.
