# PWR006 — HTML Report with Graphical Analysis

## Statement

After the test completes (or is interrupted), the framework shall generate a self-contained `power_cycle_<timestamp>_report.html` file from `result.json` containing:

1. **Summary cards**: overall verdict, cycles ran / target, pass count, fail count, per-verdict fail breakdown.
2. **Cycle timeline** (scatter chart): one coloured dot per cycle on the X axis, colour-coded by verdict, allowing instant visual identification of when failures occurred.
3. **Boot time trend** (line chart): `boot_time_sec` plotted against cycle number for all PASS cycles, revealing gradual degradation over time.
4. **Result distribution** (donut chart): proportion of each verdict across all cycles.
5. **Failure detail table**: one row per failed cycle with cycle number, verdict, power-on timestamp, boot time, and diagnostic notes.

The report shall be self-contained (no external file dependencies; Chart.js loaded from CDN). The HTML output path shall be independently configurable from the log directory via `--report DIR`.

## Rationale

Raw JSON is sufficient for programmatic analysis but not for human operators reviewing test results. Graphical data is particularly important for 1000-cycle tests: a failure at cycle 847 is invisible in a text log but immediately apparent in a timeline chart.

## Scope

`src/python/report.py`.

## Implications

- FWK028: `report.html` is a derived artefact rendered from `result.json`; the HTML file must never be hand-edited.
- CDN dependency means report viewing requires internet access; future enhancement: embed Chart.js inline.
- Dual-path output (`--out` for logs/JSON, `--report` for HTML) supports scenarios where HTML is written to a network share or NFS mount.

## Verification

Code Review: confirm HTML is generated from `result.json` data only; confirm all five sections render correctly; confirm dual output path support.
