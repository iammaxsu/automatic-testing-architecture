# SET005 — Windows DUT Pre-test Bootstrap Script

## Statement

A script `src/powershell/setup_dut.ps1` shall perform all one-time manual steps required to prepare a freshly-installed Windows DUT for automated testing. The script shall:

1. Set PowerShell execution policy to `RemoteSigned` (machine-wide).
2. Install and enable `OpenSSH Server (sshd)` with startup type `Automatic`.
3. Configure `sshd_config` to allow empty-password logins (`PermitEmptyPasswords yes`).
3a. (Optional) Install the Raspberry Pi controller's SSH public key(s) into
    `C:\ProgramData\ssh\administrators_authorized_keys` (with a strict ACL:
    `SYSTEM` + `Administrators` only) for passwordless key-based login — see
    **Pi SSH public key resolution** below.
4. Create inbound firewall rules for SSH (TCP 22) and ICMPv4 echo (ping).
5. Disable `LimitBlankPasswordUse` security policy to permit passwordless SSH over the network.
6. Set all power timeouts to 0 (never sleep or hibernate); set power button action to `Shut down`.
7. Disable Windows Update automatic reboot (`NoAutoRebootWithLoggedOnUsers`).
8. (Optional, via `-TestUser`) Configure auto-logon for the test user account.
9. (Optional, via `-DevDetectScript`) Register a Task Scheduler task `DUT-DevDetect` to run `dev_detect.ps1` at startup as `SYSTEM` with a configurable delay (default 30 s).
10. (Optional, via `-AnsibleSSH`) Configure PowerShell 5.1 as the default SSH shell by writing `DefaultShell` and `DefaultShellCommandOption` to `HKLM:\SOFTWARE\OpenSSH`, enabling Ansible to manage the DUT over SSH using PowerShell modules.
11. Install Python 3 (winget first, then a direct download fallback) and download `report.py` so `reboot.ps1` can auto-generate HTML reports.
12. Install `ipmiutil` (winget first, then a direct download fallback) for BMC firmware-version reporting (PWR015).

The script shall be idempotent (safe to run multiple times), dot-source `function.ps1`, and declare its own version with `$_script_ver`.

### Pi SSH public key resolution

The Pi controller's public key lives on the Pi, but this script runs on the DUT
(a chicken-and-egg). The operator shall **not** be required to paste the key by
hand. The script shall resolve the key(s) to install with this precedence:

1. `-PiSshPublicKey "<string>"` — a single key supplied inline.
2. `-PiSshPublicKeyFile <path>` — read key(s) from an explicit file.
3. Auto-detection — read **every** `*.pub` file located next to `setup_dut.ps1`.

Because `administrators_authorized_keys` is a **list**, ALL keys resolved shall
be installed, each **idempotently** (a key already present is not duplicated).
A key file may hold more than one key, **one per line**; blank lines and lines
beginning with `#` are ignored. This shall support multiple Pi controllers,
multiple operators, or a rotated old+new key pair in a **single run** — the
operator never runs the script once per key. A public key is not secret, so
deploying the `*.pub` file(s) alongside the scripts (USB / scp / Ansible) is
acceptable. When zero keys are resolved and the account is passwordless, key
install is skipped (steps 3 + 5 already permit login); the outcome is reported,
not silently dropped.

The Linux bootstrap script `src/bash-shell/setup_dut.sh` shall provide the
**equivalent** capability (`--pi-key`, `--pi-key-file`, and auto-detection of all
co-located `*.pub` files into `~/.ssh/authorized_keys`, one key per line, install
all, idempotent), per FWK036 cross-language feature parity. Zero-argument
auto-detection of co-deployed key files follows FWK034.

## Rationale

SSH and ping accessibility are prerequisites for all RPi-driven liveness checks (`power_cycle.py`). Consolidating these steps in a single script eliminates manual error and provides a repeatable, auditable baseline for every DUT in the test fleet.

Key-based passwordless login is needed whenever the test account has a password (a blank-password account is already covered by steps 3 + 5). Requiring the operator to paste the Pi's public key defeats the "one manual bootstrap" goal, so the key must be resolvable from a file co-deployed with the scripts. Installing *all* co-located keys (rather than picking one, or refusing when several are present) matches how `authorized_keys` actually works and removes a per-key manual step in multi-controller / key-rotation setups.

## Scope

`src/powershell/setup_dut.ps1`.

## Implications

- This script must be run once manually (physical console, RDP, or USB) before any automated test can begin — the chicken-and-egg bootstrap step.
- `SIGKILL`-equivalent process termination (hard power cut) during setup may leave the machine in a partial state; re-run the script after recovery.
- Firewall rules and Task Scheduler tasks created by this script use fixed names (`OpenSSH-Server-In-TCP`, `Allow-ICMPv4-In`, `DUT-DevDetect`) to enable idempotent re-registration.
- The Pi public key(s) are matched for de-duplication by exact line; each key must be a single unwrapped line. Auto-detection keys on the `.pub` extension, so a combined multi-key file used for auto-detection must be named `*.pub` (any filename works when passed explicitly via `-PiSshPublicKeyFile` / `--pi-key-file`).
