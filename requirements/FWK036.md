# FWK036 — Cross-Language Feature Parity

## Statement

Any operator-visible capability — a CLI flag, a configuration option, or a
test behaviour — that is provided by one language's implementation of a test
or shared helper **shall be provided, with equivalent semantics, by every
other language implementation of the same test or helper**.

The framework spans three languages (Bash, PowerShell, Python; see FWK002).
A capability that exists in only one of them is a **parity gap** and is treated
as a defect:

1. When a requirement's Scope says it applies to "all scripts and shared
   libraries", that feature must exist in the Bash, PowerShell, and Python
   counterparts **wherever those counterparts exist**. A counterpart that does
   not implement it is non-compliant with that requirement.
2. A new feature shall be added to all applicable language implementations in
   the **same change**. If parity cannot be completed at once, the remaining
   gap shall be recorded explicitly — as a tracked bug *and* in the owning
   requirement — never left silent.
3. A capability that is **intrinsically platform-specific** (e.g. a
   Windows-only power setting, a `systemd`-only restore step) is exempt, but
   the exemption shall be stated in the owning requirement's Scope or a
   per-platform mechanism table (as FWK032 does), so "absent on purpose" is
   distinguishable from "missing by accident".

## Rationale

Without an explicit parity rule, features drift between language
implementations and the divergence is invisible until a DUT on the "wrong" OS
silently lacks a capability. A concrete example motivating this requirement:
MAC-based NIC exclusion (`_net_exclude_macs`, NET012) exists in `config.ps1`
but **not** in `config.sh`, so the same management NIC cannot be pinned on a
Linux DUT — a safety-relevant gap that no single test run reveals. FWK036 makes
such gaps a named, reviewable defect class rather than an accident waiting to be
discovered in the field.

This complements, rather than duplicates, the existing cross-language rules:
FWK002 governs *how* identifiers are named in each language; FWK017 governs how
a requirement *annotates* the platforms it targets; FWK036 governs that the
*capability itself* is present everywhere it should be.

## Scope

All test programs and shared libraries across `src/bash-shell/`,
`src/powershell/`, and `src/python/`. Applies to capabilities that are
operator-visible (flags, config keys, observable test behaviour). Purely
internal implementation details that produce identical observable behaviour
are out of scope.

## Implications

1. Code review of any change that adds or modifies an operator-visible feature
   shall confirm the feature is present in every applicable language
   implementation, or that an explicit parity-gap bug exists.
2. Existing single-language features are parity gaps to be back-filled or
   documented; the first known instance to resolve is MAC-based NIC selection
   (NET019).
3. Platform-specific exemptions must be written down in the owning
   requirement, not left implicit.
4. Non-compliance must be corrected before merge.

## Verification

Code Review: for each operator-visible capability touched by a change, verify
the corresponding Bash / PowerShell / Python implementation provides it with
equivalent semantics, or that a parity-gap bug and a requirement note record
the exception.
