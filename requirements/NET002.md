# NET002 — Isolated Loopback Testing (Namespace / Weak Host Model)

## Statement

Each paired interface shall be isolated so that loopback traffic between the two
NICs of a pair traverses the physical cable between them and is not short-circuited
by the host's own stack.

On **Linux**, this isolation shall be achieved with **network namespaces** — each
NIC of the pair is moved into its own namespace with its own routing and neighbor
table.

On **Windows** (no namespaces), each pair is given a unique private /24, and —
because both NICs of the pair then sit on the same host in the same subnet — the
framework shall enable the **weak host model** (`-WeakHostSend Enabled
-WeakHostReceive Enabled`) on both interfaces, and flush the pair's neighbor
(ARP/ND) cache after any adapter Disable/Enable.

## Rationale

Without isolation, two NICs of a pair share one host stack. On Linux the namespaces
provide that isolation directly. On Windows the default **strong host model**
accepts a packet destined to a local IP only on the exact interface that owns it;
with both pair IPs local and on the same subnet, repeated adapter Disable/Enable
cycles let the duplicate on-link route and the neighbor cache drift, after which the
iperf3 control SYN is silently dropped while ICMP — which re-resolves ARP on every
ping — still succeeds. The observable symptom is a link that **pings PASS but every
iperf3 connection "times out", getting worse on each successive loop**. Enabling the
weak host model and flushing stale neighbors removes that failure and makes the
Windows path behave like the namespace-isolated Linux path.

## Scope

All scripts and shared libraries in the framework.

## Implications

1. Linux: paired interfaces are isolated into network namespaces.
2. Windows: the weak host model is enabled on both interfaces of every pair while
   under test, and restored to the strong host model (the Windows default) on
   cleanup.
3. Windows: the pair's neighbor (ARP/ND) cache is flushed after each adapter
   Disable/Enable so a stale entry cannot shadow the re-linked interface.
- Non-compliance must be corrected before merge.
