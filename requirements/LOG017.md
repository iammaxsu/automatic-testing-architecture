# LOG017 — Three-Artefact Output Model and Two Logging Modes

## Statement

Each test run shall produce a human-readable `.log` file in the session
directory. When `result.json` is also produced (per LOG015), it shall be
a sibling file in the same directory; when an HTML report is also
produced, it shall be a derivative of `result.json` (see LOG018). The
HTML report filename shall follow `<test>_report_<timestamp>.html`
(example: `net_report_20260508T090638.html`).

A test shall use exactly one of two **logging modes**:

### Discrete mode

Each iteration produces its **own** `.log` file, named per LOG008
(`<test>_<n>_of_<m>_<timestamp>_<result>.log`). Suits independent
iterations whose result is known at completion (e.g. `dev_detect`).

### Continuous mode

The whole session produces a **single** `.log` file named
`<test>_<session>.log`, plus a single `<test>_<session>.result.json`.
Per-iteration outcomes are recorded as objects in the `cycles[]` array
of `result.json` (each with its own `verdict`); the session summary is
the `summary` object in the same file. Suits long endurance runs with
many iterations (e.g. `power_cycle`, `reboot`). `result.json` is written
atomically after every iteration so progress survives interruption
(LOG023).

A **composite run** that combines a continuous-mode driver with a
discrete-mode test (e.g. `power_cycle` + `dev_detect`) produces both an
`<test>_<session>.log` (continuous) and one
`dev_detect_<n>_of_<m>_<ts>_<result>.log` per cycle (discrete),
co-located in the same session directory; see LOG024.

## Rationale

Defines the three-artefact model (`.log` mandatory; `.json` / `.html`
conditional) and recognises that endurance tests and component-detection
tests have fundamentally different logging shapes. Forcing a 1000-cycle
endurance test into 1000 discrete files is unwieldy and fragile; a single
incrementally-written `result.json` is more robust and easier to render
into reports. Conversely, independent detection runs benefit from
self-describing per-iteration filenames (LOG008).

## Scope

All scripts and shared libraries in the framework.

## Implications

- Non-compliance must be corrected before merge.
- Continuous-mode tests do not embed `<n>_of_<m>_<result>` in the `.log`
  filename (that is impossible mid-run); they use `result.json` for
  per-cycle verdicts and the session summary.
- The HTML report is a derived artefact rendered from `result.json` and
  shall never be hand-edited (FWK028).
