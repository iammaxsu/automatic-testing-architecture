# NET008 — Verdict Assignment per Test Item

## Statement

A verdict shall be assigned to each test item and recorded in the summary log and
result.json. A "test item" is the smallest reported unit — an
(interface, speed, stage) tuple — across all three stages:

- **Link stage (NET014):** `CONNECTABLE` / `NOT-CONNECTABLE` per
  (interface, speed).
- **Connectivity stage (NET005):** PASS / FAIL / UNKNOWN per
  (interface, speed, family) for IPv4 and IPv6.
- **Throughput stage (NET006/NET009):** PASS / FAIL / UNKNOWN per
  (interface, speed, combination) for the four TCP/UDP combinations.

The link verdict is distinct from the connectivity and throughput verdicts and
shall not be merged into them: a speed that is `NOT-CONNECTABLE` is not a
throughput FAIL, and its connectivity/throughput items are reported as skipped
for lack of link rather than as failures.

## Rationale

Current summary only records measured rates; no explicit pass/fail threshold is
defined. UNKNOWN is a valid intermediate verdict until NET009 thresholds are
defined. Keeping the link verdict separate from the throughput verdict lets the
report localise a failure to the correct stage — link layer vs reachability vs
performance — which is exactly what the operator needs to tell "the NIC won't
link at this speed" apart from "the NIC links but is slow."

## Scope

All scripts and shared libraries in the framework.

## Implications

1. Every reported item carries a verdict appropriate to its stage.
2. The link verdict (NET014) is recorded independently of the
   connectivity/throughput verdicts.
3. A non-connectable speed yields skipped-for-no-link items downstream, not FAIL.
4. Non-compliance must be corrected before merge.
