# NET005 — ICMP Connectivity Verification

## Statement

For each interface, and for every speed that NET014 reports as `CONNECTABLE`,
ICMP connectivity (ping) shall be verified for both IPv4 and IPv6 before the
throughput tests (NET006).

Each check shall produce a per-interface, per-speed, per-family
(IPv4 / IPv6) verdict (PASS / FAIL / UNKNOWN, per NET008), recorded in
result.json and rendered in the report. A failure shall identify which family
failed, so the operator can see whether the problem is IPv4-only, IPv6-only, or
both — and at which speed.

## Rationale

ICMP is the cheapest end-to-end reachability check and gates the more expensive
throughput stage: there is no value in running iperf3 at a speed/family that
cannot pass a ping. Reporting IPv4 and IPv6 separately, per speed, lets the
operator localise a fault to a specific protocol family rather than a generic
"network failed".

## Scope

All scripts and shared libraries in the framework.

## Implications

1. Connectivity is checked per connectable speed, for both IPv4 and IPv6.
2. Each (interface, speed, family) yields its own verdict in result.json and the
   report.
3. A family that fails ICMP is reported as FAIL for that family at that speed;
   throughput for that family/speed need not proceed.
4. Non-compliance must be corrected before merge.
