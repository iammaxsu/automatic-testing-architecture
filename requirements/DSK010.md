# DSK010 — Block-Size × Queue-Depth Sweep Matrix Mode

## Statement

disk_test.sh shall support a `--sweep` flag that runs a full parameter matrix for each safe target device:

- Block sizes: 4K, 8K, 16K, 32K, 64K, 128K, 256K, 512K, 1M, 2M, 4M, 8M (12 values; configurable via `_SWEEP_BLOCK_SIZES` in config.sh).
- Queue depths: 1, 2, 4, 8, 16, 32, 64, 128, 256, 512 (10 values; configurable via `_SWEEP_QUEUE_DEPTHS`).
- Patterns: SEQ read, SEQ write, RND read, RND write (4 patterns).
- Total combinations per device: 12 × 10 × 4 = 480 tests.

Each test shall run with `--time_based --runtime=_sweep_duration --ramp_time=_sweep_warmup` (defaults: 5 s / 1 s).

Per-device output shall be written to a timestamped subdirectory under the session log directory:

- `<dev>_sweep.csv` — one row per test, importable into spreadsheet tools.
- `<dev>_sweep.txt` — human-readable aligned table sorted SEQ/RND → read/write → block size → queue depth.
- `<dev>_<testname>.json` — raw fio JSON output per test for post-processing.

When `--sweep` is given, the normal KDiskMark-profile loop shall not run; the script shall exit after the sweep.

## Rationale

The fixed KDiskMark profiles (DSK004) cover the most operationally relevant points. The sweep provides exhaustive characterisation when evaluating new storage hardware or comparing device classes, mirroring the DiskSpd matrix approach used on Windows.

## Scope

`src/bash-shell/disk_test.sh` and `src/bash-shell/config.sh`.

## Implications

- A full 480-test sweep at 5 s per test requires approximately 40 minutes of wall time per device; operators should account for this in test scheduling.
- Sweep results are separate from the normal `result.json`; they do not feed into the standard pass/fail verdict.
