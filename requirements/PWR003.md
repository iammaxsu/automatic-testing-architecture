# PWR003 — Network-Based DUT Liveness Detection

## Statement

The power cycle test shall verify DUT alive/dead state via a two-layer network check:

1. **ICMP ping** (`ping -c N -W T`): confirms basic network reachability.
2. **TCP port probe** (default port 22 / SSH): confirms an OS-level service is accepting connections.

A DUT is considered **alive** only when both ping and TCP checks succeed. This distinguishes "still booting" (ping OK, SSH not ready) from "fully operational".

A DUT is considered **dead** when ICMP ping produces no response.

Polling behaviour:
- **Boot detection**: poll every 5 s until both checks pass or `BOOT_TIMEOUT_SEC` expires.
- **Health check during ON_TIME**: probe every `HEALTH_CHECK_INTERVAL` seconds.
- **Shutdown detection**: poll every 5 s until ping fails or `DEAD_TIMEOUT_SEC` expires.

Liveness checking shall be skippable via `--no-check` for relay-only testing without a networked DUT.

## Rationale

Single-layer ping can miss cases where the DUT kernel has crashed but the NIC keeps responding. Two-layer checking catches OS-level failures and distinguishes them from network-level failures.

## Scope

`src/python/liveness.py`, `src/python/power_cycle.py`, `src/python/config.py`.

## Implications

- DUT IP/hostname must be configured before liveness checks are meaningful; if `DUT_HOST` is empty, checks are automatically disabled.
- Fixed IP is the primary implementation; DHCP support (discovery via MAC or hostname) is a future enhancement.

## Verification

Automated Test: confirm boot detection returns `(True, elapsed)` when host comes online; confirm shutdown detection returns `(True, elapsed)` when host goes offline; confirm timeout returns `(False, timeout_sec)`.
